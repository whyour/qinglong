# 2.x Shell → TypeScript CLI migration

## Scope and acceptance

Migrate product logic from every 2.x `shell/*.sh` file, retaining originals for differential evaluation. `ql3-launcher.sh` belongs to the separate 3.0 implementation and is excluded. User configuration, hooks and user shell programs remain Bash inputs; invoking a user script does not count as delegating product implementation to the original Shell.

Completion requires all rows below to have an implementation and behavioral evidence. A new entrypoint or API client alone does not satisfy this migration. The current requirement-by-requirement audit is [acceptance-status.md](acceptance-status.md); evaluation.md retains chronological evidence and failed attempts.

## Architecture decision

The agreed ownership is a public panel-management CLI plus independent local execution/operator tools. Subscriptions are managed through panel APIs; repo/raw are internal worker operations. See [command ownership](command-scope.md). Migrating every capability does not mean exposing every legacy command publicly.

Use TypeScript with strict checking and Node's `util.parseArgs`; no runtime npm dependencies. Keep the existing Node >=18 floor. A declarative command registry supplies names, aliases, argument/option schema and generated help. Separate parsing, rendering, command handlers and system adapters. Use lazy imports so remote commands/help do not load local configuration, backend DI or a database.

Alternatives considered:

- Commander: established commands/help, built-in TS definitions; a sound alternative, but adds a versioned dependency and latest major has a higher Node floor. The bounded command tree here fits native parsing plus a small schema registry.
- yargs/oclif: more conventions and extension machinery than this CLI requires.
- Continuing handwritten argv parsing: rejected; standard `--key=value`, short options, option terminators and duplicate validation should not be reimplemented independently per command.
- Python: would introduce another language boundary alongside the existing TS backend and need its own packaging story. Keep Python support as a task runtime.

Sources: https://nodejs.org/download/release/latest-jod/docs/api/util.html#utilparseargsconfig and https://github.com/tj/commander.js/releases . Verify footprint by measuring cold process wall time, peak RSS and packed artifact bytes, rather than assuming zero dependencies means zero overhead.

## Contracts

- Remote `task run/stop` addresses task IDs through the API; local `exec` executes a file/command. Separate these meanings to prevent accidental local execution.
- Preserve legacy ql/task/qinglong argument forms with explicit compatibility adapters; do not replace installed binaries until evaluation gates pass.
- `--json` produces one result envelope; streamed process output and diagnostics go to stderr or log files. Never buffer unbounded task logs in memory.
- Exit status distinguishes invocation failures from the actual local child result. Signals reach the entire process group; timeout has a bounded TERM/INT-to-KILL grace period.
- Filesystem and process operations accept argv arrays and explicit cwd/env. No interpolated eval for product logic. Bash is confined to user-owned config/hooks/scripts.
- Each operation owns an environment snapshot; no mutation of global process.env for one command or one account.
- Preserve script arguments after `--` byte-for-byte. Do not parse child flags as CLI flags.
- Fetch/download failures must not replace known-good files. Cron deletion only follows a successful scan; scope reconciliation to the target subscription.
- Keep 2.x preload integration and lifecycle API evidence (including scheduled_system execution IDs) intact.
- No hidden daemon, plugin auto-discovery, or startup network access for help. Future commands extend the registry and load one handler.

## Evaluation gates

A historical full-suite snapshot passed in dedicated Debian ARM64 and Alpine ARM64 / Node 18.20.8 test images: 113 tests on each, followed by offline package installation verification. Later work expanded the suite; the latest recorded full host run passed 167 tests with two Linux-only skips (169 total), including startup compatibility and common/authentication/API diagnostic localization. Targeted Linux follow-up runs passed. These snapshots are not a claim that the final tree has received a new full cross-platform run. See evaluation.md and test/linux/README.md. This establishes cross-platform execution of the fixtures; simulated package-manager/service operations and loopback APIs still require real panel deployment validation.

`test/differential.test.cjs` copies the unchanged legacy task/otask/share/api/env and language files into a temporary panel, replaces only token generation with an inert fixture, and runs the same shell script/hooks through legacy and TS. now/desi/conc traces agree on config functions, selected accounts, hook invocation and shell-state isolation. Concurrent trace lines are compared without relying on process scheduling order. Additional cases cover `/dev/null` routing, nonzero return, explicit exit, errexit termination and EXIT traps with `no_tee=true`; see evaluation.md for exact scope and intentional exit-code differences. Subsequent differential fixtures cover pipefail, nullglob, disabled braceexpand/extquote, errexit/nounset and hook option overrides. Independently detached processes, arbitrary trap transfer and unsupported Bash-version options remain outside that evidence. CLI-level signal fixtures prove original SIGINT/SIGTERM/SIGHUP forwarding to running Shell sessions, matching traps, final JSON and conventional 130/143/129 cancellation statuses. Random-delay cancellation also produces final JSON and matching status without starting the task. Independent and same-session after-hooks also receive cancellation signals and preserve the final cancellation status; already-cancelled tasks skip independent after-hooks. Configuration and independently evaluated before-hooks now use the common process-group cancellation mechanism; CLI fixtures verify matching traps, cancellation status and no task startup. Configuration-stage cancellation emits an error JSON rather than a task result. Independently detached descendants and more complex user traps remain outside this evidence.

Concurrent account output is spooled to private temporary files, then streamed into the task log in selection order after all children settle, matching legacy ordering. Temporary files are removed on success or invocation failure. Concurrency still follows the selected account count; output size does not accumulate in parent memory. Output-sink failure kills the active writer and rejects the operation. POSIX timeout/cancellation fixtures cover descendants holding pipes after the leader exits; generic cancellation returns 143 (explicit INT/HUP return 130/129), timeout 124, and a pre-cancelled request never spawns. Shared-shell hook state has retained-Shell differential evidence; independently detached descendants remain outside process-group cleanup guarantees.

1. Existing remote CLI tests remain green.
2. Fixtures compare legacy and TS behavior for script selection, cron metadata, config, account selection, workdir, hooks and logs.
3. Real subprocess tests cover argv, output, nonzero exit, timeout and signal propagation.
4. Local HTTP fixtures cover lifecycle and subscription API requests; local git repositories cover sync and failure preservation.
5. Maintenance plans are tested using controlled executables/filesystems; destructive release/upgrade operations never target a live installation during tests.
6. Package installation, independent copied artifact, help usability and startup/RSS measurements pass.
7. Verify every scope row; report unverified real-platform integration separately. Retain old Shell and default entrypoints until replacement is explicitly evaluated.

## Operator candidate limitations

Subscription file-copy precedence now matches legacy gen_list_repo: previous files, notification defaults, repository dependencies, local dependency overrides, then selected task scripts. A local Git fixture compares conflicting task/helper/notification files against the unchanged gen_list_repo function extracted from shell/update.sh; only its directory-creation helper is supplied by the fixture. It also verifies repository notification fallback when the local override is removed. This is focused copy-order evidence, not full subscription workflow parity.

Subscription replacement handles EXDEV by copying into a private sibling of the destination before moving the old directory aside. Fault-injection fixtures verify successful cross-filesystem preparation and preservation of old files when preparation fails. Real multi-mount testing remains part of Linux evaluation; scripts/repository/API reconciliation are not a single transaction.

Loopback lifecycle fixtures verify matching scheduled-system execution IDs across start/end, log paths, actual failure exit codes and elapsed statistics. Final status and dashboard recording are independent attempts: rejecting the status update does not suppress the statistic or change the script's exit code. These fixtures validate request contracts, not persistence in a real panel database.

Script-path fixtures cover nested directories with spaces, absolute script paths, explicit work_dir precedence, and exact child arguments. Missing script directories retain the original path and fail instead of running an unrelated basename in the default directory. This does not yet establish every preloader's handling of unusual installation paths.

The migrated runner now ships its own Node/Python language adapters, derived from the retained preloaders and embedded in the TypeScript build. It creates a private temporary adapter directory per execution and links the panel's generated environment, client, notification and ESM modules there. Both adapters invoke Bash through an argument array for the Shell before-hook, passing the hook path and original task arguments separately. This intentionally fixes the old unquoted-path behavior and gives language before-hooks the full task argv, including empty and quoted arguments. User inline hooks remain executable user configuration. The original shell/preload files are unchanged for comparison. The temporary adapter directory is removed after task execution; adapters are not a replacement for the installed panel's generated modules or Python/Node runtimes.

The previously failing five-language installation-path gate now passes on macOS and Node 18 Alpine. Additional actual JS/Python tasks verify literal quotes, dollar signs, semicolons, empty arguments and command-substitution-looking strings, restored preload environment and adapter cleanup. These checks do not establish every ESM global-package resolution case or arbitrary user-hook behavior.

The ESM resolver is also packaged with the adapters. It selects the package root (including scoped names) before passing resolution to Node with an encoded file URL, preserving native import conditions, exports and private-subpath rejection. This fixes the old loader's treatment of `#`/`%` paths and its requirement that a requested export name exist as a same-named file. Global pnpm packages retain priority over system global packages, with ordinary local resolution when neither provides the package. Real task fixtures cover special-character global paths, mapped exports, scoped/pnpm-linked packages, package-internal `#imports`, CommonJS default imports, global-over-local precedence, local fallback, relative/data/builtin imports and rejection of an unexported file. The generated panel environment/client/notification modules remain external; the old ESM loader file stays untouched for comparison.

Task dependency-path fixtures exercise actual Node module loading from a pnpm global directory, fallback when pnpm is absent, and restoration before after-hooks. The optional pnpm root probe is bounded to five seconds and 64 KiB. Environment construction does not mutate the caller's environment. Real sitecustomize.js/sitecustomize.py fixtures cover JS, ESM, TypeScript, Python source and Python bytecode generated environment, shell/language before-hooks, designated account selection, QLAPI setup and after-hook exit status. Network adapters are inert in those fixtures. The TypeScript fixture uses the installed repository ts-node with explicit CommonJS compiler options, and pyc is compiled by the test interpreter. ESM global-package and unusual installation-path checks now pass as detailed above and in evaluation.md.

Task hook fixtures verify that a before-hook can define the inline before command, exported values reach the script and after hook, and task_after.sh shares variables/functions with the inline after command. Language preload variables are restored before after-hooks. Ordinary/now/designated .sh execution uses one Bash session for generated env, before hook, script and after hook; tests cover unexported variables/functions, exact script arguments and script exit status. Designated selections are passed through the child environment and applied after before-hooks; a fixture verifies selected accounts plus private script state. Additional fixtures prove that config.sh functions survive Bash automatic export through the environment bridge without sourcing config twice. Concurrent shell tasks inherit before-hook functions, isolate their script mutations, merge logs in account order and run the after-hook once with pre-execution state. These focused fixtures do not yet replace full differential execution against legacy Shell across shell options, traps and exits.

`repair-config`, `update` and `reload` are available only in `ql-local-cli`. Upgrade staging validates paths and rejects archive symlinks before extraction, waits for both archives/dependencies, and retains prior files until service startup succeeds. Failure recovery is process-level, not crash-atomic; rollback does not establish application health or database rollback. PM2 success currently means its command succeeded; direct Node startup only detects immediate exit. Do not replace production entrypoints based on these fixture results.

The mirror is explicit (`--mirror github|gitee`, default github), replacing the old Google-connectivity heuristic. `--download-only` returns staged paths and atomically records the latest complete stage per branch. A later system reload uses that record, validating its directory and readiness marker before stopping services. Failed later downloads preserve the prior record. Without a record, system reload reads the legacy `.tmp/qinglong-<branch>` and `.tmp/qinglong-static-<branch>` locations. Branch selection retains master/develop/debian/debian-dev. Linux direct-process discovery reads NUL-separated argv and resolves the script against each process cwd. It accepts the legacy relative entry and the new absolute entry, including installation paths with spaces and symlink aliases, while rejecting other installations and command shapes. Non-Linux fallback retains exact absolute-path ps matching. Mock /proc fixtures verify selection. A Linux-only fixture additionally launches two real relative-entry Node services, verifies scoped termination, and exercises direct Node startup/logging/stop without disturbing the other installation. It passes in Node 18 Debian; delayed shutdown and HTTP port handoff now pass a real Linux fixture. Direct restart waits up to five seconds for the selected old backend to disappear; an unresponsive old service causes failure before a replacement is spawned. No automatic SIGKILL escalation is used for panel shutdown. Concurrent external launches and process-title changes are not covered.

`check` retains the legacy repair semantics: install global tools, fill configuration templates, install panel production dependencies, overwrite notification helpers from samples, diagnose and reload. It adds post-reload observations and bounds PM2 log tails to 300 lines / 256 KiB per file. HTTP checks use loopback directly with a five-second deadline and one-MiB body limit. Diagnostics report observed health, not guaranteed readiness; package/reload failures stop the operation. PM2 logs respect `PM2_HOME` or the user's home instead of always reading `/root/.pm2`.

`bot` preserves the default/custom repository selection, main branch, Alpine/Debian/Ubuntu package lists, existing bot.json, and python3 -m jbot invocation. Repository and runtime files are staged; failed downloads preserve existing files and failed startup restores the previous tree and requirements file. Python dependencies use pip's requirements parser rather than the old per-line pip-show heuristic: pinned versions and markers are now honored. Installed package changes are not rolled back. Process discovery requires Linux and scopes matches to the current installation's data directory. A surviving startup process does not prove Telegram connectivity. A separate real Alpine OS/pip installation and Python replacement/isolation gate has passed using a local test bot. Telegram connectivity was not exercised. Container shutdown now also covers a bot that outlives its installer; see the dedicated Linux container-bot gate.

`start [--reload]` carries the start.sh bootstrap into the local operator entry: OS prerequisites, global Node tools, Python requests, nginx reload/start fallback, PM2 service startup, optional bot/extra background jobs and PM2 startup/save. Reload skips installers, optional jobs and startup registration. The data directory must end in /data. Startup hooks call the new admin entry directly, never the installed legacy ql command. Their returned PIDs indicate dispatch, not successful completion; their output is in bot.log/extra.log.

Bootstrap differences: existing .env is preserved and a new one is mode 0600; dependency caches honor the configured data directory; inherited PATH is retained; product Shell files are not chmodded to 777. A missing explicit root is reported by the common local CLI rather than searching global npm/pnpm modules. PM2 startup/save are skipped when direct Node fallback is used. System paths retain /etc/nginx and /run/nginx defaults. Real Alpine package-manager and full-panel first-start integration has passed in an existing official image. With prerequisite Bash/Node/npm/Python/pip runtimes installed, real Alpine provisioning and OpenRC registration/reboot now pass, including nginx/crond/PM2 and a retained task triggered by cron after reboot. Debian 12/systemd has actual reboot and automatic retained-task execution evidence; Ubuntu has shared-path fixtures only. This does not claim automatic provisioning of the prerequisite interpreters.

## Developer release candidate

`ql-dev-cli release --root /repository` returns a plan without changing refs or uploading CDN metadata. It requires a clean checkout and reads version.yaml from HEAD. `--apply --commit <full-SHA>` executes the reviewed commit; origin/master are defaults and can be selected explicitly. Release credentials remain in the existing environment or ignored .env file. Qiniu and dotenv are loaded from the release repository's installed dependencies, not bundled into the management CLI.

Compatibility differences are intentional: only the release tag is pushed; remote branch and tag changes use an atomic push with explicit leases instead of deleting tags and blindly force-pushing. Servers without atomic push support fail rather than falling back to partial ref updates. CDN upload now fails on non-200 responses, and precedes the remote ref update. CDN and Git cannot form one transaction: a concurrent remote update can reject the push after CDN upload succeeded. Local branch/tag changes and CDN uploads are not rolled back; inspect state before retrying. No production release is authorized or performed by migration tests.

## Remaining completion gaps (2026-09-25 audit)

The source capability audit and final packaged deployment now establish completion of the requested migration. See [the current acceptance audit](acceptance-status.md) for the requirement mapping and tested boundaries. GitHub/Gitee archive staging, native Git/netrc authentication, full-panel upgrade and Alpine/OpenRC plus Debian/systemd reboot recovery all have evidence. Ubuntu-specific whole-machine boot remains a platform measurement limitation, not an unimplemented command.

Subscription include/exclude/dependency expressions now use the local POSIX ERE engine (`grep -E`) through argv arrays and a private temporary file. This preserves existing expressions and the installation's locale without evaluating a Shell string. Invalid patterns stop before publishing a new scripts tree or reconciling tasks. Newline-containing paths are rejected when filtering rather than splitting into unrelated names. The internal local worker requires grep, alongside its existing git/curl tools; public API commands do not load or invoke this adapter.

Official 2.20.1 switched-entrypoint integration also verifies resetname/resetpwd/resetlet/resettfa against actual login behavior and persisted settings, including a dash-prefixed password and rejection before clearing retry/second-factor requirements. All accounts are temporary fixture accounts.

Host startup registration now covers nginx and the system cron daemon as well as PM2. OpenRC installs nginx/crond in the default runlevel and starts crond immediately; Debian/Ubuntu systemd installs cron when necessary, enables nginx and enables/starts cron. nginx is already started or reloaded by the existing bootstrap stage, so registration does not issue a second start against that unmanaged PID. The init system owns nginx after the next boot. Registration failures fail the command instead of reporting full success; earlier completed package/service changes are not rolled back. `start --reload` and `start --no-startup` skip these host registrations, preserving container/externally supervised operation.

Raw HTTP(S) subscriptions honor the selected HOME/.netrc through curl --netrc-optional. Missing netrc does not prevent public downloads. TLS certificate verification remains enabled; the legacy raw downloader disabled it. This is an intentional security difference.

Final migration status is complete in acceptance-status.md. Chronological caveats above describe the evidence available at those earlier stages; evaluation.md records subsequent closure, including all six signals, script discovery and native Bash 3.2 shopt state.
