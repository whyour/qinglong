原生 SQL / ORM 审计与热点修复（2026-11-24）

当前结论
优先 ORM 适用于普通 CRUD；任务执行热路径按真实测量保留参数化 SQL。
后端原生 query 调用点：原始 228 → 全面 ORM 后 91 → 本轮 134；恢复 43 处，仍保留 94 处 ORM 转换。
8 个普通建表迁移继续使用 QueryInterface；环境排序继续使用 fn/col。模型定义、普通配置/历史查询、低频取消与恢复管理操作不随热点回退。
本轮只修改 6 个执行相关源码文件中的 18 个方法，适配 1 处故障注入测试，并更新本审计文档。没有提交、发布或修改既有 dev 业务容器。

定位方法
1. 在 dev 独立采样真实执行链路。36 次触发中，预算快照 137 次、预算 pump 112 次；启动和结算关键方法通常每次任务各调用一次。插桩数据仅用于定位，不进入性能结论。
2. 四组独立消融，每组只恢复对应方法的旧 SQL；当前 ORM 与改写前 SQL 各作基准。每个版本独立容器，预热 1 轮 + 正式 3 轮。
3. 独立 SQLite 微基准每组 5 轮交替顺序、每轮 400 次操作，预热 40 次。沿用 DELETE journal、synchronous=EXTRA、IMMEDIATE 写事务；对比双方数据库语句次数相同。
4. 最终候选与两个基准按 SQL → final → ORM → ORM → final → SQL 顺序交叉；每个批次预热 1 轮 + 正式 3 轮，各版本共 6 轮、54 个短任务样本。全部轮次保留。

可靠性
- 正式对比 432 次触发：独立脚本记录和账本 ID 一致，每个 ID 唯一；每轮 18 次启动、18 次完成，状态均 finished/exit_code=0，中文 UTF-8 stdout/stderr 行内容和顺序完整，并发峰值 <=4。
- 每个正式容器结束后租约、等待表均为 0。初筛另有 432 次触发，所有轮次日志、唯一执行和并发断言通过。
- 最终候选真实故障验证包含 HTTP 手动 worker SIGKILL、gRPC 定时 worker SIGKILL、运行中/排队取消、执行超时 124、排队超时、system-crond 与手动混合、32 次连续取消，以及 JS/Shell 对应故障和三种语言钩子。
- Python 中断任务将已写日志行数写入独立落盘记录；与保存日志逐行相等。JS/Shell 使用独立已发出行记录核对前缀；正常完成任务要求全部行一致。故障期间采样实际进程身份，并发峰值 4；各场景结束后无 queued/running 任务、无租约和等待条目。
- 取消和排队超时属于明确终止，要求不再启动；其余已接受任务不得漏跑、重复运行。此结论限于被测执行身份、回执记账与已发出的日志，不代表任意外部业务副作用的 exactly-once 保证。
- 本地全量 1481 项：1461 通过、20 跳过、0 失败。Linux 专项 78/78 + 回执边界 36/36，共 114/114 通过、0 跳过。
- npm run prettier、npm run prettier:check、后端构建和 git diff --check 通过；690 文件无格式问题。
- GitNexus 已刷新。与 develop 比较的累计差异为 CRITICAL（40 文件、124 符号、72 流程），包括之前未提交工作；本轮独立哈希/AST 核对仅涉及选定方法，不能把累计差异全部归因于本轮。

保留边界
保留旧 SQL 的事务对象、状态/NULL 条件、受影响行数、身份 token、参数绑定、回执顺序和唯一键语义。没有缩小耐久性配置，也没有用先查后写替代条件更新。
普通 CRUD 使用原有按连接注册的模型映射；不会让独立 worker 偷用全局连接，也不会用模型 sync 代替版本迁移。
新增的 43 处性能例外按方法/链路分组验证，不表示每一个分支中的每一条 SQL 都独立带来可测的端到端收益。

其他原生片段
连接 PRAGMA、展示状态的 CASE/相关证据子查询、清理保护性子查询和 CURRENT_TIMESTAMP 保留原有语义。
CLI 原生 sqlite3 探针验证驱动本身；测试和压测的 SQL 作为独立存储判据保留。Shell/Python 执行脚本没有新增数据库 SQL 入口。
