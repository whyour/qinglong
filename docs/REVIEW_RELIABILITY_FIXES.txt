Review 可靠性修复验收（2026-11-24）

修复范围
1. 日志不再直接连接业务脚本的 stdout/stderr。独立日志进程负责排空管道，写盘失败记录错误后继续排空，避免 ENOSPC/EFBIG 中断脚本。
2. supervisor 等待后台写入者及日志排空后才发布退出回执。Linux 通过 subreaper 接管孤立子进程，保留全局并发名额和可取消的进程树。
3. 排队诊断改从全局预算已有的共享快照采集，覆盖同步批量提交、其他 worker 和其他执行入口的占用。维持 250 ms 合并写入、内容去重及出队/终态写保护，界面标注“全局执行队列”。
4. 全量回归发现并修复日志目录创建竞态：existsSync 与 lstatSync 之间出现的普通目录继续经过 realpath、根目录和黑名单检查；新出现或替换成越界符号链接的路径仍拒绝访问。

验证结果

dev：3 个顺序创建并自动删除的独立容器，每轮 59/59 通过，0 跳过；退出回执故障边界及共享队列另 34/34 通过。共 211 次通过。
dev 容器限制：2 CPU、1536 MiB、512 PID。未修改既有业务容器。
真实后台任务与全局上限 1 联动：正常完成及强制取消均验证另一连接不能提前取得名额、结束后租约清空、只执行一次、日志完整。
日志故障：普通文件触及 RLIMIT_FSIZE、/dev/full、打开失败、日志接收端断开；业务后续操作及退出码不受日志错误影响。
停止/恢复：后台子进程纳入取消树、忽略 TERM 后强制停止、supervisor 被停止/杀死后已确认输出仍落盘；已有取消、超时、worker 恢复及回执 SIGKILL 边界回归通过。

定位过程保留
首次本地全量暴露了旧测试对日志同步可见性的假设。改为有期限等待已确认字节完整落盘，保持业务写入者存活、supervisor 已被杀死，不通过结束写入者掩盖日志丢失。
新增 dev 联动夹具最初使用默认 DEFERRED 事务，出现 SQLITE_BUSY 锁升级失败。改为加载生产 back/data/index.ts，使用实际 IMMEDIATE 事务及重试配置；未放宽生产事务或可靠性断言。
随后本地全量捕获同目录并发启动被路径检查拒绝，已用确定性目录创建竞态复现并修复，另测新建越界链接、悬空链接和目录被替换成越界链接。
一次 dev SSH 认证失败发生在容器启动之前；只读连接确认恢复后继续验收。
