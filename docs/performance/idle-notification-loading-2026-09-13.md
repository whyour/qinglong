# 通知依赖加载：负向试验与队列清理（2026-09-13）

本轮未发现可确认的空闲 CPU 或实际常驻内存收益。撤回 SystemService 和 nodemailer 按需加载，只保留删除 TaskLimit 中未使用的 NotificationService 导入和实例。重复任务提醒仍通过既有 gRPC 调用发送。

## 对照方法

基线为 `7c6e9b9ed`，试验为 `97db17b3f`，后者包含两项按需加载及未使用实例清理。两容器使用相同数据种子、脚本和依赖，Debian ARM64、Node 20.20.2、PM2 7.0.4；各限 2 CPU、1 GiB 内存，不增加 swap，保留默认 5 秒 exec curl 健康检查。无强制 GC。

完成相同任务和恢复验证后，分别在首次通知前、首次通知后测量 5 分钟，每组每阶段 61 个样本。首次调用使用真实 mTLS gRPC，显式未知通知类型 -1，两组均返回 400，没有外部通知投递。两个阶段连续进行，不能当作独立重复试验。准备阶段中断的采样不纳入结果。

## 结果

| 阶段 | 版本 | 平均 CPU | 工作集中位数 MiB | 匿名内存中位数 MiB | 结束时四个 Node 进程 PSS 合计 MiB |
| --- | --- | ---: | ---: | ---: | ---: |
| 首次通知前 | 基线 | 0.981% | 145.36 | 132.84 | 157.59 |
| 首次通知前 | 试验 | 0.964% | 145.50 | 133.10 | 158.49 |
| 首次通知后 | 基线 | 0.935% | 149.48 | 137.01 | 161.98 |
| 首次通知后 | 试验 | 0.926% | 150.73 | 138.14 | 162.55 |

工作集、匿名内存和 PSS 均未改善。CPU 差值很小，短窗口不足以确认稳定收益。试验在首次通知前将 gRPC 模块数从 1110 降至 1014，首次调用后升至 1074；HTTP 从 1421 降至 1385。模块数和 JS heapUsed 减少没有转化为本轮容器常驻内存节省，因此不保留相应复杂度。

各测量窗口无服务重启、OOM 或 worker PID 变化。空闲后两组任务均成功完成且日志完整。不同轮次运行历史和内存状态不同，不与此前报告相加或跨轮比较绝对值。最终仅保留的实例清理没有单独进行资源归因测量，不宣称新的内存或 CPU 降幅。

## 最终保留版本验证

- 完整本地回归 190 项：187 通过、0 失败、3 项 macOS 平台跳过；后端 TypeScript 构建通过。
- 新增队列行为回归：实际 PQueue 并发上限、重复任务拒绝和最多三次 gRPC 提醒；无本地通知实例创建。
- 最终镜像 `qinglong-idle:queue-cleanup` 实测：正常退出、退出码 7、1 MiB 日志、手动停止、5 任务并发及秒级调度通过。
- gRPC 不可用时健康接口返回 503；gRPC 和 HTTP worker 恢复后各完成三次调度。
- 试验版的首次通知、并发首次邮件调用等回归曾通过；随按需加载撤回，相关试验专用测试移除。
