# WebSocket 会话轮询合并（2026-09-14）

每个连接原先创建一个每秒定时器，分别读取同一份认证数据。现改为每个 HTTP loader 共享一个每秒定时器、每轮一次读取，随后使用原有 isValidToken 逐连接校验。首次连接仍独立读取并认证，最后一个连接关闭后停止定时器。

读取未完成时跳过新一轮，避免慢数据库查询堆积；一轮开始时固定连接集合，读取期间接受的新连接不使用旧快照。初次认证读取失败时断开，认证返回前已关闭的连接不会再加入客户端列表。

## 本地传输对照

基线 `b0846b3e8`。两版分别启动实际 SockJS 服务，由 20 个本地 WebSocket 连接接入；使用相同签名 JWT 和内存认证数据替身，统计 getAuthInfo 调用。初次连接各自的 20 次读取不计入周期窗口。

| 指标 | 原版 | 修改后 |
| --- | ---: | ---: |
| 3.1 秒周期窗口内认证读取调用 | 60 | 3 |
| 撤销后全部断开的实测等待 | 802 ms | 786 ms |
| 最后一个连接断开后的 1.2 秒读取次数 | 0 | 0 |

周期读取调用减少 95%，不是 CPU 减少 95%。本轮没有测量 SQLite 查询耗时、容器 CPU 或内存；无客户端时原版同样没有这些定时器，因此不宣称无客户端空闲收益。撤销延迟为本次采样结果，受定时器相位、事件循环及数据库延迟影响，不是时限保证。

新增回归覆盖多连接共享读取、撤销和重新连接、慢查询不重叠、新连接不受旧快照影响、存储失败、认证前关闭，以及 JWT 到期和平台会话到期。原有真实定时器撤销回归继续保留。后端 TypeScript 构建通过。

本地复现脚本和结果保存在 `docs/research/websocket-session-polling-20260914/`。脚本仅绑定 127.0.0.1，使用测试 JWT，不涉及真实登录凭据或外部通知。
