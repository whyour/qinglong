# 按进程角色加载：空闲资源验证（2026-09-13）

## 变更与范围

基线为 develop `4eb27427f`，候选仅延迟加载 HTTP 应用、中间件和恢复消息使用的 CronClient，并抽取独立的错误格式化模块。保留 PM2、主进程与 HTTP/gRPC 两个 worker、数据库初始化顺序和默认 5 秒健康检查。

先前基于旧提交的准备阶段遇到调度锁与 crontab 文件锁冲突。同步 develop 后确认 #3070 已修复，本轮采用该远端修复，没有重复提交；此前容器的数据不计入正式性能结果。

## 环境与测量

- Docker Desktop Linux VM：8 CPU、约 3.82 GiB 内存；Debian ARM64。
- 每容器限额：2 CPU、1 GiB 内存、无额外 swap。
- Node 20.20.2、PM2 7.0.4、@grpc/grpc-js 1.14.0、Sequelize 6.37.5；两版使用同一依赖锁文件和镜像运行时。
- 四组同时观测：基线/候选 × 5 秒/30 秒 Docker 健康检查。5 秒组保持 20 次失败阈值，30 秒组为 3 次；理论连续失败判定窗口约 100/90 秒，但单次发现及恢复确认速度不同。
- 四组从同一独立种子数据卷复制，经相同类型任务和故障恢复验证后空闲。定时实例数、时间戳和日志尺寸会因实际执行时间略有差异。
- 空闲阶段无面板页面和业务 API 轮询；每 5 秒通过 Docker API 读取容器累计 CPU 时间与 working set。CPU 按单核 100% 口径计算。
- 首尾读取 `/proc` 的 PSS、CPU ticks、进程启动时间；通过只在 SIGWINCH 时运行的诊断钩子记录堆内存、模块与活跃资源，不增加周期性采样定时器。
- 采样期间另有少量只读版本及产物核对命令，其 CPU 计入样本，未剔除。
- working set 与 PSS 口径不同，不直接相加。未人为调用 GC，不修改堆上限。
- 后端按各自源码构建；前端静态文件相同且未在观测期访问。本轮不是与白虎或之前 Alpine 镜像的重新对比。

## 性能结果

四组各观测约 1800.04 秒，361 个样本全部保留。窗口内所有容器及 worker 的 PID/启动时间保持一致，无重启、OOM，结束时健康状态均正常。

| 版本 | 健康检查周期 | 平均 CPU（单核） | working set 中位数 | working set 起始 → 结束 |
|---|---|---:|---:|---:|
| 基线 | 5 秒 | 1.462% | 182.9 MiB | 175.5 → 189.8 MiB |
| 候选 | 5 秒 | 1.436% | 164.2 MiB | 157.5 → 167.7 MiB |
| 基线 | 30 秒 | 0.473% | 177.0 MiB | 173.3 → 179.5 MiB |
| 候选 | 30 秒 | 0.457% | 163.8 MiB | 160.4 → 166.8 MiB |

- 保持默认 5 秒探测：候选的 working set 中位数减少 **18.7 MiB（10.2%）**；30 秒组减少 **13.1 MiB（7.4%）**。两组均显示内存下降，但不是跨主机、跨运行时的固定节省承诺。
- 相同 5 秒探测下 CPU 仅从 1.462% 到 1.436%，差异很小，不能据此认定加载优化有稳定的 CPU 收益。
- 对同一候选镜像，将探测从 5 秒改为 30 秒，CPU 从 1.436% 降到 0.457%，本次下降 **68.2%**。这是降低探测频率的部署收益，不能归因于应用代码提速。
- 各组结束时 working set 均高于起始值；没有强制 GC。这一 30 分钟窗口不能证明没有长期内存泄漏。

### 5 秒探测组的常驻进程归因

| 进程 | CPU 基线 → 候选 | 结束时 PSS 基线 → 候选 |
|---|---:|---:|
| pm2 | 0.168% → 0.147% | 19.7 → 16.3 MiB |
| primary | 0.008% → 0.002% | 40.7 → 30.2 MiB |
| grpc | 0.134% → 0.134% | 52.9 → 48.1 MiB |

主进程和 gRPC worker 的 PSS 减少是主要可解释的内存收益。HTTP 的 CPU 没有下降。四个常驻进程 CPU 之和低于容器总量，余量包含短生命周期健康检查等进程及采样差异；不能将全部容器 CPU 记在 HTTP 名下。5 秒候选中四个常驻进程约占 0.662%，容器总量为 1.436%。

## 部署选择

本次代码不修改健康检查默认值。容器部署若接受较慢的单次故障发现/恢复确认，可对现有启动参数增加：

```sh
--health-interval=30s --health-retries=3
```

该配置降低探测频率，不替代真实 readiness 检查，也不代表调度服务内部开销按相同比例下降。
