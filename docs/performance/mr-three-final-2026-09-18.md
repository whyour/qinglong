# 三项核心优化：最终整体对照（2026-09-18）

本轮直接对比整个 MR 与 develop 基线：空闲匿名内存减少 **28.35 MiB（17.2%）**；20 个共享 Token 连接时容器 CPU **6.438% → 3.438%（下降 46.6%，3.000 个百分点）**，匿名内存减少 **29.93 MiB**。空闲 CPU 仅减少 0.054 个百分点，不据此宣称稳定提速。

## 范围与方法

- 基线：MR 的 develop 基线 `4eb27427f`；候选：仅保留三项优化的 `bec64cc14`。
- 同一个 Debian ARM64 镜像运行时、依赖和前端；两版后端分别从对应源码编译。运行中的全部后端 JavaScript 已逐文件校验 SHA-256。
- 每版两个独立容器，各 2 CPU / 1 GiB，不增加 swap；均保留默认 5 秒原始 curl 健康检查。四组同机并行，体验容器在观测期间停止。
- 同一数据种子独立复制，先完成成功/失败退出、1 MiB 日志、停止、五任务并发和秒级调度预热，再等待 60 秒。
- 无客户端空闲 5 分钟；然后每容器真实登录并建立 20 个共享 Token、同平台的 WebSocket 连接，等待 60 秒，再观测 5 分钟。客户端位于宿主机，每 30 秒发心跳，没有页面 API 轮询。
- 每阶段每容器 61 个样本，间隔 5 秒；不强制 GC。CPU 按累计 CPU 时间增量计算，100% 为一个核心满载。工作集 = usage − inactive_file；匿名内存为 anon；PSS 是四个 Node 进程的结束值之和。

## 进程归因

- 空闲结束主进程 PSS：两副本均值约 40.59 → 12.71 MiB，减少约 27.89 MiB。HTTP 的空闲 CPU 没有下降。
- 连接阶段 HTTP CPU：约 4.416% → 1.458%，减少约 2.958 个百分点，解释了绝大部分容器 CPU 差值；HTTP 结束 PSS 没有减少。
- 当前观测的空闲 CPU 和多连接总 CPU 绝对值与历史轮次不同，不跨轮比较；本轮结论基于同时运行、相同设置的组内对照。

## 有效性与限制

- 两阶段容器/worker 生命周期检查通过，无重启或 OOM，结束健康；连接阶段 80 个连接全程保持，采样后四组再次执行任务通过。
- 这是整个三项优化相对 MR 基线的对照，不与此前各轮收益相加。本轮没有重测白虎。
- 两个副本共用一台 Docker Desktop 主机，每场景单个五分钟窗口，不能代表独立机器重复实验或长期内存行为。
- WebSocket 结果适用于共享 Token、同平台的多连接场景，不外推到每连接独立 Token、单连接或任务执行负载。
- 工作集包含文件缓存，归因需结合匿名内存与 PSS；两阶段均无新增 CPU 配额限流，所有样本均保留。
