# WebSocket 轮内 JWT 复用：真实资源对照（2026-09-15）

本轮保留 CPU 优化：20 个共享 Token 的真实连接下，容器平均 CPU 3.683% → 1.447%，下降 2.235 个百分点，约 60.7%。两个副本均下降，主要来自 HTTP 进程。无客户端 CPU 未显示明确收益，内存也未改善。

## 改动及安全边界

上一轮已合并认证数据读取，但每个连接仍重复验证 JWT。本轮只在一次同步检查中，对同一份认证数据、同一 Token、同一平台复用验证结果。结果表在当前调用结束后释放；下一轮重新读取认证数据、校验签名和有效期，首次连接依然独立认证。不同 Token 或平台不会共用结果。

新增回归验证每轮重新校验、失效结果复用、不同 Token/平台隔离；原有过期、撤销、读取失败、慢查询、新旧连接隔离测试继续通过。本地 Node 20 完整回归 207 项：204 通过、0 失败、3 项 macOS 平台跳过。后端 TypeScript 构建通过。

## 实测方法

- 基线为 `ab72e53ca`（WebSocket 代码来自 `818fa4a74`，已包含共享读取），候选在相同镜像上只替换 WebSocket loader 的编译产物和源码。镜像 ID 和候选源码 SHA-256 见结构化结果。
- 每版两个独立容器，各限 2 CPU / 1 GiB，不增加 swap；5 秒真实 exec curl 健康检查不变，同一份数据种子、依赖、脚本和前端。
- 四容器先通过相同真实任务预热，完成正常/失败退出、1 MiB 日志、手动停止、五任务并发及秒级调度；本地回归结束后再启动正式采样。
- 预热等待 60 秒，采样无客户端 5 分钟；每容器建立 20 个真实 WebSocket 连接、等待 60 秒，再采样 5 分钟。每阶段每容器 61 个样本。
- 每容器的 20 个连接共享该容器一次真实登录取得的 Token，模拟多页面共享登录凭据；实际读取容器内 SQLite 认证数据。客户端在宿主机运行，每 30 秒发应用心跳，没有页面 API 轮询。
- CPU 根据 Docker 累计 CPU 时间增量计算，100% 表示一个核心满载。工作集为 usage − inactive_file；匿名内存取 anon；PSS 为四个 Node 进程的结束值合计。未强制 GC。

## 结论与限制

- 无客户端平均 CPU 0.933% → 0.926%，差异很小，且轮内验证代码未运行，不归因于本次优化。
- 20 连接平均 CPU 3.683% → 1.447%；HTTP 分项约 2.929% → 0.684%。这是上一轮共享读取之上的增量对照，不能把不同轮次的绝对占用或百分比相加。
- 20 连接匿名内存均值 162.00 → 163.85 MiB，结束 PSS 均值 175.47 → 176.51 MiB。未测出内存节省，也不能将工作集副本差异全部归因于代码。
- 平均值是两个副本指标的算术均值。四容器共享一台 Docker 主机，不是独立机器重复试验；两个副本、单个五分钟窗口不提供长期统计保证。
- 收益依赖连接共享 Token 和平台，不外推到单连接、每连接不同凭据、无客户端、其他请求负载或长期内存行为。
- 两阶段容器与 worker 的生命周期稳定，无重启/OOM；80 个连接全程在线。采样后再次执行真实任务检查退出码、日志及健康状态。
