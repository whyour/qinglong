# 健康检查成本归因与 exec curl（2026-09-13）

## 保留的改动

四份 Dockerfile 的健康检查从 `curl ... || exit 1` 改为 `exec curl ...`。shell 仍负责端口变量展开，然后由 curl 替换自身，减少一次派生和等待子进程。探测频率 5 秒、超时 2 秒、20 次失败阈值、健康接口 URL、代理绕过和真实调度 readiness 均保持原值。

curl 失败时现在保留其原始非零退出码，例如 HTTP 错误为 22、连接拒绝为 7；此前统一返回 1。两者均使 Docker 将本次探测记为失败。没有新增定时器、缓存就绪状态或常驻进程。

## 四组诊断

基线为 `843fc0e1f`，运行上一轮独立数据库初始化镜像。四组使用同一 Debian ARM64 镜像、相同种子数据、2 CPU/1 GiB 限额、Node 20.20.2 和 PM2 7.0.4，仅覆盖 Docker 健康检查配置。完成相同类型任务测试后，观测各 300.02 秒、61 个样本，全部保留。

| 诊断组 | 平均 CPU（单核） | 用途 |
|---|---:|---|
| 原 curl 命令，5 秒 | 0.882% | 生产基线 |
| exec curl，5 秒 | 0.841% | 候选 |
| 空命令 true，5 秒 | 0.614% | 仅测探测启动成本，不检查应用 |
| 关闭 Docker 探测 | 0.125% | 仅测没有 Docker 探测时的底噪 |

**空探测和关闭探测不是生产方案。** 它们不提供原有故障发现能力，实验容器已在验证后停止。

空探测与关闭探测的差值约 0.490 个百分点，说明启动探测进程及其运行时路径占据了较大开销。这是本机诊断归因，不是对 Docker 内部各组件的精确测量；不能把全部容器 CPU 算给 HTTP。

候选与基线差约 0.040 个百分点，但 PM2 分项同时由 0.093% 变为 0.070%。因此，不能将容器总差值全归因于 exec，也不承诺稳定的整体 CPU 降幅。

两组常驻进程结束时 PSS 合计均约 150.0 MiB。working set 差异包含文件缓存等因素，本轮不宣称新的常驻内存收益。不同轮次运行历史和缓存不同，不跨轮比较绝对值。

## 单次命令成本

在同一容器内交替执行六轮，每轮每种命令 100 次，使用 `RUSAGE_CHILDREN` 累计 shell/curl 的 CPU 时间；不包含 Docker exec 启动器和 HTTP/gRPC 服务端 CPU。该微基准在空闲观测结束后单独运行。

| 命令 | 每次探测 CPU 时间中位数 |
|---|---:|
| 原命令 | 3.842 ms |
| exec curl | 3.677 ms |

六轮中 exec 均略低，保留这个仅改变四行配置的优化。每次约节省 0.165 ms，按每 5 秒一次折算仅约 **0.0033 个 CPU 百分点**，说明它无法解释全部 0.040 个百分点的容器差值，也不足以让空闲 CPU 出现大幅下降。

## 未采用的方向

当前健康接口为读取 heapUsed/heapTotal 调用两次 `process.memoryUsage()`。官方说明该接口会收集页面信息，成本可能随内存分配变化；这两个字段属于 V8 堆指标。[Node.js 20 文档](https://nodejs.org/docs/latest-v20.x/api/process.html#processmemoryusage)

在同一 Node 镜像中保留 20 万个对象，对双次采样、单次采样及 V8 堆统计分别进行五轮交替微基准，每轮预热 1000 次、测量 20000 次。CPU 时间中位数为 5.694、3.034、0.204 微秒/次。该局部实验的最大差值按每 5 秒一次折算约 0.00011 个 CPU 百分点，对当前空闲场景不值得扩大改动，因此没有修改健康服务的内存采样代码。

历史上健康接口快速路径与合并内存采样的组合实验也未得到可靠空闲 CPU 收益，本轮没有重做该路由改造。

## 功能与产物验证

- 四组均通过正常退出、退出码 7、1 MiB 完整日志、手动停止、5 任务并发及秒级调度。
- 空闲观测期间容器及 worker PID/启动时间不变，无重启或 OOM；观测和故障验证后再次执行任务，退出码为 0、日志完整、应用健康接口正常。
- 原命令与 exec 命令均验证：显式端口 5700 成功，端口 1 连接拒绝；设置不可用 HTTP 代理后仍通过 `--noproxy '*'` 成功。
- 两组分别暂停 gRPC，Docker 实际探测记录失败，恢复后退出码回到 0；暂停 HTTP 则实际触发 `Health check exceeded timeout (2s)`，恢复后同样成功。
- 候选镜像由原运行时镜像叠加实际 Dockerfile 的 HEALTHCHECK 声明构建，其探测配置与实验容器的 CLI 覆盖配置完全一致。未修改后端产物或依赖，不是全发行构建矩阵重跑。
