# 登录 IP 地址查询：真实资源对照（2026-09-18）

本轮保留优化：同一来源重复登录负载下，平均 CPU 5.227% → 3.179%（约 -39.2%），匿名内存中位数均值 223.52 → 209.20 MiB（减少 14.32 MiB）。登录停止后的五分钟，匿名内存均值 225.82 → 215.10 MiB（减少 10.72 MiB）。未测出明确的空闲 CPU 收益。

## 改动

旧代码每次登录新建 IP2Region，加载 IPv4 和 IPv6 库，共约 10.87 MiB。新代码最多缓存 64 条 IP 对应的地址文字，五分钟后访问时刷新，不保留数据库对象或 Buffer，不缓存认证结果，也不增加清理定时器。IPv4 查询跳过 IPv6 库，IPv6 保持原行为；普通与双因素登录共用 helper。

若运行期间更新地址库，已缓存的展示结果最多延迟五分钟刷新。密码校验、IP 封禁、重试计数、认证数据读取及登录限流保持原逻辑。

## 方法

- 基线 `ce6961869` 已包含前几轮优化。候选在相同镜像上仅替换 UserService 并加入 helper；镜像 ID、源码 SHA-256 见 JSON。
- Docker Desktop ARM64：8 CPU、4106604544 字节内存、内核 7.0.12-linuxkit。每版两个副本，各 2 CPU / 1 GiB，不增加 swap，保留 5 秒 exec curl 健康检查。
- 相同数据种子和真实任务预热：正常/失败退出、1 MiB 日志、手动停止、五任务并发及秒级调度。已确认种子未配置外部通知。
- 三阶段：预热后无客户端 5 分钟；每容器每 5 秒一次登录，共 60 次/5 分钟；停止登录后空闲 5 分钟。每容器每阶段 61 个样本，不强制 GC。
- 四组登录来自同一宿主机来源，走真实 HTTP API、密码校验、SQLite、Token 更新和日志写入。全部 240 次成功，保留原 15 分钟 100 次限流。
- 客户端在宿主机运行。CPU 按累计时间增量计算，100% 是一个核心满载；工作集 = usage − inactive_file；匿名内存取 anon；PSS 是四个 Node 进程的窗口结束值之和。
- 首次准备在第一个样本前因诊断快照写入未完成而失败，未产生有效采样。采样器改为删除旧快照、等待完整新快照后读取，随后重跑；失败准备未混入结果。

## 解读与限制

- 登录前空闲 CPU 1.477% → 1.495%，匿名内存 137.73 → 137.01 MiB，未显示明确改善。
- 重复登录：两副本 CPU 和匿名内存均下降；CPU 平均下降 2.048 个百分点，结束 PSS 均值 235.50 → 223.40 MiB。
- 登录后空闲：CPU 1.474% → 1.490%，未改善；匿名内存减少 10.72 MiB，结束 PSS 237.57 → 225.94 MiB（减少 11.63 MiB），主要差异来自 HTTP。
- 登录期各容器出现 1–5 次短时 CPU 配额限流，累计 throttled_time 约 0.019–0.389 秒；两个空闲阶段没有新增限流。所有样本保留，结果适用于本次 2 CPU 配额配置，不能代表不限核的峰值性能。
- 均值是两副本指标的算术均值。四容器共用同一主机，CPU 存在同向波动；工作集受文件缓存计费影响，不能单独归因。本轮匿名内存与 PSS 同时支持该负载下的内存收益。
- 单个短窗口不是长期统计保证，不外推到不同来源 IP、稀疏登录或长期空闲，不与前几轮的节省量相加。
- 三阶段无重启、OOM 或 worker PID 变化；采样后四容器再次运行真实任务验证成功。
- 新增真实 IPv4/IPv6 输出一致性、缓存上限/过期、空结果和失败重试回归。Node 20 本地完整回归 212 项：209 通过、0 失败、3 项 macOS 平台跳过，后端构建通过。
